01 / Three findings

The result is a trade-off, not a single winner.

The same data supports three practical conclusions about latency, CPU, and pinning.

Fast, but burns cores

Spin-based shared memory leads small-message RTT while keeping roughly two cores busy under back-to-back load.

Blocking stays close

Pipe, FIFO, MQ, and futex-backed shared memory cluster far more tightly than their labels suggest.

Same-core spinning collapses

With both endpoints pinned to one CPU, the capped spin path becomes the slow outlier.

07 / Context

Method, limits, and a clean rerun.

Method

Five cross-core repetitions and three same-core repetitions are aggregated by median with min–max retained. Payload integrity, cleanup, watchdogs, futex diagnostics, and ring wrap-around are tested separately.

Limitations

WSL2 virtualization, one host, scheduler noise, frequency scaling, and unreadable governor state limit generalization. Same-core shm_spin uses its measured capped iteration count.
